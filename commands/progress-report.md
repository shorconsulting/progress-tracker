Produce today's build-progress report and publish each repository's report as its own artifact. Run unattended:
never ask a question, never stop to confirm. The report is generated by a script; your job is to run it, publish
its HTML, and summarize.

## Steps

1. Run the generator (it reads the repository list from `~/.claude/progress-tracker/repos.json`, creating it from
   the plugin default on first use; `PROGRESS_TRACKER_HOME` overrides that directory):

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/progress.py" report $ARGUMENTS
   ```

   Where `python3` is not installed (Windows), run the same command with `python`. It prints a markdown summary
   and the paths of `report.html` and `report.json` (under `~/.claude/progress-tracker/out/<date>/`, with a copy
   in `out/latest/`). It needs GitHub read access through
   `gh` or a `GH_TOKEN` / `GITHUB_TOKEN`, and a local checkout of each repository for the frontend / backend /
   wiring columns: it uses the current working directory when it is a clone of that repository, else keeps a
   blobless clone under `~/.claude/progress-tracker/repos/`. If a repository fails, the others still report; the
   failure is listed at the end of the output. It also writes one page per repository and prints a line for each:
   `page <owner/repo>: <path> (artifact title: <Title> build progress)`.

2. Publish each repository's page as its own artifact, never one repository's report over another's. Call the
   Artifact tool with `action: "list"` once, then for each `page` line:
   - when an artifact has exactly that title, publish the page to its `url` so the link stays the same day to day
     (read it first if this session has not published it);
   - otherwise, when an artifact is titled `Build progress` (the single-artifact name earlier versions used) and
     reading it shows it holds only this repository, publish to its `url`, which keeps the old link;
   - otherwise publish a new artifact with `icon: "chart"` and the description
     `Daily build progress by module for <Title>`.
   Do not publish the combined `report.html`.

3. Reply with the markdown summary the script printed (the overview line per repository and the per-module table)
   followed by each repository's artifact link. Keep the module order exactly as printed (M00, M01, M02 ...). If
   the script reported a warning or a failed repository, say so in one line each.

## Notes

- `% complete` per module = done tracked issues / all tracked issues, where done means merged work (a merged PR or a
  default-branch commit naming the issue) and marked done (closed or labelled `done`). Deltas (1 day, 7 days) are recomputed from GitHub timestamps, so the report needs no
  earlier run and works the same from any account.
- `Done 1d` counts requirements closed (or, when still open, labelled `done`) in the last 24 hours whose work has
  merged, dated by the close rather than the first PR, so a day spent closing long-running requirements shows.
- Frontend / Backend / Wired columns come from the module probes file named in the repository's config entry
  (`config/modules/<name>.json`); a repository without one reports issue and PR progress only.
- To change which repositories are reported, use `/progress-repos` or pass `--only` / `--skip`.
